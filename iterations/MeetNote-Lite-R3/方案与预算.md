# MeetNote Lite R3：单台 200–300 元路线评估

日期：2026-09-29。独立低成本分支，R2 金属版源文件及评审页保持原状。

**结论：接近 300 元的自装实验机有条件成立；200 元完整实现 Linux + FPGA + 摄像头 + 双麦 + Wi-Fi + TF + 外壳，目前没有可信的采购闭环。**
本版是选型与预算研究，不是已适配硬件、可下单 BOM 或生产文件。当前目标合计 **¥296**，距 300 元仅余 **¥4**；各项估算上下界合计 **¥245–403**，上下界不是同一商家的成套报价。15% 预备金后为 ¥340.4。

## 范围与取舍

- 以现成主控板、FPGA 板、相机板、麦克风板自行接线组装；不在单台预算内重新设计 BGA/DDR 主板，也不计外包焊接和开发人工。
- 保留知情同意后的录制、物理控制、明显指示、拍照、加密分片、TF 暂存、Wi-Fi 续传、服务器生成摘要与用户确认。双麦不自动等于有效波束成形。
- 基础版借用已有 5 V USB 电源或充电宝，不含新购电源；内置电池、屏幕、GNSS、加速度计、蓝牙分别列为增配。这是 Lite 的候选范围变更，不覆盖 R2。
- 本地运行 Buildroot/Linux、采集与轻量 DSP；转写/摘要留在服务器。64 MB 内存需要精简 C/C++ 服务、受控图像缓冲与 TLS 堆，不默认部署浏览器、Docker 或本地大模型。
- 摄像头按键按需拍照，不承诺自动对焦和远距离白板细字识别。外壳为平板亚克力盒，先验证桌面/手持使用；不继承金属挂坠版的外观、密封及佩戴指标。

## 架构与 FPGA 的真实收益

```text
两路数字 MEMS → I²S/PDM 接收 → 小 FPGA → SPI + IRQ → RV1103 / 64 MB DDR2
                                 │                       ├→ TF：系统 + 加密数据
                                 └→样本计数/溢出标志      ├→ USB Host → Wi-Fi → 服务器
SC3336 摄像头 ───────────── MIPI CSI 2-lane ───────────────┤
物理录制许可/状态灯/拍照键 ───────────────────────────────┘
```

**1K 路线（预算主线）**：Tang Nano 1K 的 GW1NZ-LV1 提供 1152 LUT4、864 FF、72 Kbit 块 RAM。做同步接收、时间/样本计数、小 FIFO 和帧级峰值/过零统计；DC 去除及定点滤波须先综合证明资源足够。这里的主要价值是确定时序和卸载采集，不是已经证明的 AI 运算提速。官方资源表没有列出 1K 的硬乘法器，不将乘法密集 FIR/FFT、神经网络降噪列入承诺。

**9K 路线（更适合运算实验）**：Tang Nano 9K 有 8640 LUT4、20 个 18×18 乘法器与 468 Kbit 块 RAM，可研究定点 FIR、抽取、短窗特征计算。预算增量先按 ¥35–65、目标 ¥45；目标整机变为 ¥341。尚未进行综合、时序和吞吐验证，不能把硬乘法器数量视为算法已经能实时运行。

**不装 FPGA 的对照组**：保留同一主控和输入质量，测 CPU 占用、丢样、延迟、输入功率与音质。只有 FPGA 在其中至少一项有可重复收益时才固化。音频规模很小，Linux SoC 的 NEON 或自带 NPU 可能更划算。NPU 的 0.5 TOPS 也不代表任意转写模型能运行；模型算子、量化与内存适配要单独验证。

摄像头直接进 SoC 的 ISP，不能绕过 SPI 去让 1K FPGA 接收 MIPI 高速图像。FPGA 不负责 TLS、文件系统或 SD 协议，可减少实现成本。

## 接口预算与关键约束

- 48 kHz、双声道、24-bit 紧凑 PCM 为 288 kB/s；I²S 32-bit 双槽时位时钟为 3.072 MHz。麦克风具体协议及最低时钟范围尚未选定，I²S 与 PDM 是替代路线，不能混接。
- 目标 SPI 12 MHz，假设有效载荷效率 50%，约 750 kB/s，数学上覆盖 288 kB/s；驱动是否支持持续 DMA/中断读取仍未验证，先不要用 Python 轮询作正式音频通路。
- 1K 的 72 Kbit RAM 总量仅 9 KiB。假设能分到 8 KiB FIFO，原始 PCM 缓冲约 28.4 ms；若 FPGA 已正确滤波抽取至 16 kHz/16-bit 双声道则约 128 ms。8 KiB 是拟议分配，不是综合结果，Linux 调度长停顿仍可能溢出。
- 固件必须输出帧序号、样本计数和溢出计数；一旦丢样明确记录证据缺口。更大 Linux 缓冲不能挽回 FPGA 到主控之间已丢的数据。3.072 MHz 麦克风时钟需证明可实现的频率精度及抖动，不能任意整除 27 MHz 后假定正确。
- USB 被 Wi-Fi 占用时，ADB/USB 网络调试不可同时假设存在；保留 UART 调试。供电经经验证的 Host 电源转接/5 V 输入，防止两个电源反向灌电。
- Mini 仅 17 GPIO。SPI4 + IRQ1 + 控制复位1 + UART2 + 按键2 + 许可1 + 指示2 + I²C2 共 15 个是需求统计，不是可实现 pinmux；需逐脚核查复用、启动脚、1.8/3.3 V、电源默认态和 IRQ。未锁引脚前不画成已连通原理图。
- Wi-Fi 的具体 USB 芯片、版本、ID、内核驱动及固件仍是阻断项；厂商仓库 issue #156 曾明确表示 RTL8188EUS 未经其验证。此历史记录只证明存在适配风险，不代表今天所有型号都不支持。

## 摄像头、麦克风与 TF

SC3336 3MP Camera (B) 有官方 Mini A/B 支持说明，2304×1296、手动对焦、水平视角约 84°。先把镜头调到典型使用距离并固定；数字裁切不会产生新细节。预算优先留给有驱动的相机、真实低噪声麦克风与声学隔离，避免买不兼容的高像素裸模组。官方 MIS5001/IMX415 兼容清单并未把 Mini 列为适配目标。

麦克风当前为占位：采购前核实供应商、料号、SNR、灵敏度差、最大声压、电源与协议。先两路对称布置并做增益校准；机壳、手持摩擦、Wi-Fi 电源噪声和镜头调节声可能比算法更影响结果。通孔加声学网/软垫，传声孔不能被胶封死。

Mini A 用原有 TF 卡座启动，壳体侧面露出卡槽，卡座零件不重复计价。**系统卡不可工作中拔出**。若必须热插拔纯数据卡，改 Mini B 从 NAND 启动并验证镜像及卸载流程，或增加第二存储接口，重新计算费用。TF 延长线会增加接触/信号问题，首版不采用。

## 功耗、续航、容量、尺寸：设计估算

电功率预算：Linux/DDR 0.6–0.9 W，按需相机平均 0.15–0.30 W，FPGA/麦克风 0.20–0.40 W，Wi-Fi 平均 0.20–0.45 W，存储/指示/转换损耗 0.25–0.45 W；合计 1.4–2.5 W，系统评估取 1.5–2.5 W，峰值预留约 4 W。所有分项均未经实测；Wi-Fi 低占空比和相机关断是重要假设。先配有裕量的现成 5 V / 2 A 电源，并核查板上电源路径承载能力。

基础版无内置电池，因此不承诺独立 2 小时续航。选配 2000 mAh/3.7 V，85% 转换效率、80% 可用能量，则有约 5.03 Wh：2 W 约 2.52 小时，2.5 W 约 2.01 小时，衰减/低温/峰值没有进一步余量。若必须稳定覆盖 2 小时应实测后增加容量或降功耗，不能仅凭标称容量验收。

2 小时双声道 48 kHz/24-bit 原始 PCM 约 2.074 GB；16 kHz/16-bit 约 0.461 GB；Opus 合计 64 kbps 约 57.6 MB（编码负载尚未测试）。每分钟一张、单张假设 2 MB，2 小时另用 240 MB。32 GB 卡先预留系统/升级 4 GB，数据分区保持至少 20% 余量；切片及加密开销另计。不把音频、相机和软件峰值同时挤满 64 MB RAM。

亚克力使用 2 mm 面板、平板切割、M2 铜柱/螺钉，可拆后盖。空间起点 **90×70×30 mm（不含突出线缆）**，只是开发板与接线的预留目标，未完成真实三维装配校核。内置电池或长 USB 网卡可能增加尺寸。开口至少包括镜头、两路传声孔、TF、USB、按键和灯；对插线、FFC 弯曲与拔卡留空间。透明板在镜头周围加黑色遮光片，避免指示灯眩光。用局部开槽和内部散热片处理热量；亚克力不是金属散热器，不作持续贴肤温度或防水承诺。无 PCB/STEP，因此本轮不出伪精确切割文件。

## 软件边界与验收顺序

采集 → 帧序号/时间戳 → VAD/轻量 DSP → 每 30 s 加密切片 → TF 原子落盘 → HTTPS 上传带分片哈希和确认 → 重传未确认片 → 服务端转写/摘要 → 原始时间戳与片段链接 → 用户确认。断网不停止录制，空间不足和丢样必须显示。加速度事件可建议记事，不得绕过知情同意或物理录制许可自动开启采集。

加密实现选成熟库，独立设备密钥与不重复 nonce；禁止将密钥直接与密文一起明文放在可拔 TF 上。Mini A 没有已验证的安全密钥存储方案；首版可用用户解锁加载会话密钥，脱网自主重启录制与密钥持久化是待解决项。软件升级采用签名镜像、恢复卡和先停录制再升级；不在 64 MB 首版强行同时实现复杂桌面/容器。

建议先做三项实测：
1. **音频链与 FPGA 收益**：采集同时写卡、拍照、TLS 上传，连续 2 小时读帧序号和溢出计数；对照 CPU 路线测音质、延迟、CPU 占用及输入功率。先综合 1K 资源/时序，再判断是否值得保留或改 9K。
2. **相机、无线与内存共存**：选定 SDK/USB ID/相机版本，测白板典型距离文字可读性、弱网续传和 RSS 峰值；64 MB 下不得因缓存导致 OOM 或音频断流。
3. **供电、热与断电恢复**：同时发射 Wi-Fi 和保存照片测瞬态压降，亚克力闭壳运行 2 小时测温；受控断电检查文件和恢复，电池版另验证真实续航与提前关机。

## 本轮验证记录

- 已查阅官方型号、资源、兼容清单、主控系列标价、相机海外标价，以及厂商仓库的无线适配讨论。
- 本机只计算预算、带宽、FIFO 时长、存储与能量；输出在 verification/预算与带宽计算.json，可由 scripts/build_review.py 重现。
- 没有运行 RTL 综合、目标板程序、ERC/DRC、CAD 干涉、射频、声学、热或电池测试；没有生成新 KiCad/FreeCAD 文件，没有下单，也没有更改 R2。
