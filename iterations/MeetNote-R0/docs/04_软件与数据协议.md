# 软件与数据流程

## 状态机及模块

`OFF → BOOT_SELFTEST → LOCKED_IDLE → CONSENT_READY → RECORDING → FINALIZING → QUEUED → UPLOADING → SERVER_PROCESSING → NEEDS_CONFIRMATION → CONFIRMED`。

从任何采集状态切断物理许可：立即停止MIC/摄像头硬件采集，封存已有分片并记录原因；新启动不继承同意。断网仅切换上传状态，不能停止本地录制。采集与上传是正交状态，不允许上传线程反压导致采集阻塞。

设备模块：硬件许可/指示与按键、FPGA DMA/SPI读取、采样计数和UTC映射、音频HPF/降噪/限幅/VAD、帧/段队列、照片原图及裁切参数、本地能量/长静音/手工标记事件、可选小词表关键词检测、AES-GCM暂存、SQLite WAL索引、断点上传、BLE配网、健康监视与签名更新。本机参考程序**只实现加密分片、原子保存、模拟续传及候选任务证据结构**；VAD/降噪/关键词、实际FPGA接口、相机驱动和服务部署未实现。

FPGA计划：12.288MHz输入、3.072MHz PDM、4路抽取/CIC+FIR、24bit PCM、单采样计数；每20ms一帧，SPI首部包含协议版本/启动epoch/帧序号/首采样计数/样本数/溢出位/CRC。SPRAM环形缓冲满时不得静默覆盖；停止覆盖并上报明确的lost_samples区间，仍能继续记录后续段。滤波器系数、资源综合、静态时序、SPI时钟域交叉与形式验证均未完成，本交付不包含可下载bitstream。

## 文件与元数据

每会一个UUID，每次启动一个boot UUID；音频每10s独立分片。生产音频：Opus 16kHz单声道32kbit/s（可选FLAC/原始4ch PCM用于调试）；照片JPEG原图+裁切矩形和AF/曝光元数据。时间字段优先使用`start_sample/sample_count/sample_rate`与`monotonic_ns`，另存UTC锚点及不确定度，NTP跳变不能改变已录时间轴。示例参考程序格式是PCM16单声道，不能误称已实现Opus。

`.mn`参考格式：4字节`MN01` + 4字节大端头长度 + canonical JSON AAD + AES-256-GCM密文（末尾含16字节认证tag）。AAD含meeting_id、boot_id、consent_event_id、sequence、采样范围、格式、nonce、key_id；AAD可见，不能放会议标题/姓名。密文文件SHA-256用于传输完整性，不能替代GCM认证。元数据中的身份/内容字段也必须进入独立加密manifest；本例测试未实现生产manifest服务。

每会随机256bit DEK，生产系统使用安全硬件/用户密钥解封本地DEK，并在需要服务器处理时以服务器KMS公钥包装DEK，TLS上传密钥信封。设备自身可解密，所以不能称服务器不可见的端到端加密。Zero 2 W无已集成安全元件的证据，**本地防失窃密钥保护是阻断项**，不能把密钥与SD上密文放在一起就声称失窃保护。RAM里处理明文，不写未加密临时文件/崩溃转储。

nonce随机96bit，每会使用独立DEK并设置分片数上限、检测重复，失败就重建新会话key；不能把重启后归零的序号直接当重复nonce。使用成熟密码库，不实现自制密码。

## 上传与服务API草案

完整机器可读API见 `software/openapi.yaml`。所有网络端点生产要求TLS与设备认证；token scope绑定tenant/device/meeting，不能由客户端任意指定访问者。BLE只承载通过实体键发起的限时配网交换、Wi-Fi凭据和状态，不传会议内容。BLE会话也需加密配对/防重放，不能广播SSID密码。

1. POST /v1/meetings：幂等键、同意事件、格式版本，返回meeting UUID。
2. POST /v1/meetings/{id}/uploads：创建绑定chunk UUID/密文SHA/大小的upload。
3. HEAD /v1/uploads/{id}：返回已持久化Upload-Offset。
4. PATCH /v1/uploads/{id}：上传二进制片段，严格校验offset/Content-Length；409后HEAD重对齐。不要每次重试重新加密同一个逻辑chunk而改变已上传字节。
5. POST /v1/uploads/{id}/complete：完整长度和SHA正确后幂等提交；只有服务端持久化确认后设备才允许清理本地缓存。
6. POST /v1/meetings/{id}/process：授权解封、转写、说话人匿名分段、OCR、摘要和候选任务。job_id异步查询。
7. GET /v1/meetings/{id}/results：每条结果附原始chunk SHA及样本区间/照片ID；模型/提示模板版本、置信提示、人工修改历史。
8. POST /v1/meetings/{id}/confirmations：人工确认/修改/拒绝，需结果版本与If-Match，防止误确认过时建议。未确认的“决定”不产生工作流副作用。

转写器、OCR与摘要模型均为适配器接口，模型/服务器/GPU未指定，不能声称转写质量已经测试。负责人不清楚留null；“下周五”保留原文、会议时区和推导结果，用户确认日期。将转写内容当作数据，不执行其中的提示指令或链接。

## 恢复、低电量与更新

- 分片先`.partial`，fsync后原子rename，再事务更新索引。启动时扫描孤立已完成文件恢复索引；未完成文件隔离，绝不提交错误长度/错误GCM的数据。已完成分片不可变。
- 当前参考程序模拟单写者；生产服务需数据库事务/租约，防并发PATCH竞态；限额、对象存储一致性、授权撤销、日志脱敏均需补齐。断点测试只证明磁盘模拟行为。
- Wi-Fi重连指数退避+随机抖动，5xx/408/429按Retry-After；401刷新身份后最多重试一次；403停止并提示；422隔离坏分片。设备USB供电时可提高上传占空比，但温度优先。
- 电量预测剩余15min提示、5min关闭相机和上传、2min封存并正常关机；瞬时欠压立即结束当前段并保存状态。阈值应以电量计/负载/内阻实测校准，不只凭固定电压。过温同样先降相机/无线，再停止录制明确报警；不可无提示丢数据。
- 采用OS A/B槽、签名manifest/镜像、版本反回滚策略、设备健康确认及失败回滚；更新前必须停止录制、接电或足够电量并有恢复入口。独立救援分区只读。FPGA bitstream和主机协议版本绑定，不可跨版本混用。
- 保留策略30天默认可改；服务端访问审计与删除状态、密钥销毁和备份过期联动。SSD/SD磨损均衡下单文件覆盖不是可证明的物理抹除。
