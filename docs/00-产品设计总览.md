# MeetNote 产品设计总览

> 整理自 R0–R3 四轮研究交付物｜2026-09-29｜状态：工程概念研究，非量产设计

这份文档把四轮迭代里的产品定义、交互、形态、架构、成本与验证边界压缩成一条可读的主线。所有数字都是**设计估算或本机计算**，不是实测结论；细节与证据请沿文末链接回到各轮原始文档。

---

## 1. 一句话与目标用户

**MeetNote 是一个可挂佩、以按键为入口的 AI 记录助手：随手把话和画面记下来，本地先可靠保存，联网后由服务器理解，再把带证据的回答和候选事项交回给用户确认。**

目标用户是日常工作、学习和会议中频繁产生「临时信息」的人：需要快速记下一个念头、拍下一页白板、会后找回某个决定，但不愿意每次都掏手机、解锁、打开应用。

R1 明确把定位从 R0 的「会议记录器」调整为「**圆润、可挂佩的 AI 助手**」，会议记录保留为核心模式，而不是唯一场景。

## 2. 要解决的问题与价值假设

产品赌的是三件事，且都还没有真实用户验证：

| 假设 | 现状 | 怎么验证 |
|---|---|---|
| 高频用户愿意把设备戴在身上 | 未验证；R2 金属样机估算 155–190 g，明显偏重 | 等重模型做 ≥30 min 日常动作、衣物摩擦、挂绳摆动测试 |
| 按键说话比掏手机开应用更方便 | 未验证 | 用同样 10 个任务对比成功率与完成时间 |
| 简短回答 + 证据入口真的有用 | 未验证 | 若用户主要需要长文本，应优先手机显示，而不是不断加大屏幕 |

由此得到一个明确的产品边界：**不做全天候记录，不做默认常开唤醒词，不做本地通用大模型**。设备的价值在「主动发起的那一下」，而不是「一直在听」。

## 3. 使用场景与三种姿态

| 姿态 | 典型场景 | 设计含义 |
|---|---|---|
| 胸前挂佩 | 走动中记一个念头、临时拍照 | 优先收佩戴者语音；不能承诺等效桌面全向阵列 |
| 手持取景 | 拍白板、投影、材料 | 摘下后屏幕朝向使用者；AF + 1×/1.5×/2× 数字裁切 |
| 桌面会议 | 4–8 人、0.5–3 m、连续 2 h | 沿用 R0 的会议条件；启动前必须确认参会者知情同意 |

多人会议建议桌面摆放，这是对「胸前麦克风收不全会议室」的诚实妥协，而不是靠算法话术掩盖。

## 4. 产品闭环与 MVP

主闭环：

```mermaid
flowchart LR
  U[用户主动发起] --> C[语音 / 照片采集]
  C --> L[本地加密分片保存]
  L --> S[服务器理解<br/>ASR / OCR / 摘要 / 检索]
  S --> A[简短回答 / 候选事项]
  A --> V[用户核对与确认]
  V -. 确认后才产生副作用 .-> X[提醒 / 日历 / 对外动作]
```

三个 MVP 动作（R1）：

| 动作 | 用户路径 | 成功条件（目标，未实测） |
|---|---|---|
| **记住这件事** | 按住助理键说话，松开发送；断网先存本地 | 屏幕 + 短振动明确「已保存」或「保存失败」；不能把已保存显示成云端已理解 |
| **看一下这个** | 相机键唤醒取景，单击拍照；长按助理键补充问题 | 照片与问题绑定到同一请求；识别不清要求重拍，保留原图 |
| **帮我回顾** | 询问自己已授权的记录，在屏幕或手机看摘要/待办 | 每条结论可追到记录时间与证据；找不到就明确说没找到 |

会议模式是独立的**长录制模式**：显式确认后连续记录 2 h，停止后后台整理，网络变化不结束采集。

## 5. 形态设计

形态经过三轮收敛，每一轮都保留了上一轮文件：

| 轮次 | 形态 | 尺寸（宽×高×厚） | 质量（估算） | 说明 |
|---|---|---|---|---|
| R0 | 桌面台架壳 | 82×118×29 mm | 120–160 g | 模块化验证平台，不追求佩戴 |
| R1 | 圆润挂佩目标 | 68×90×26 mm，平面圆角 R12 | 65–95 g | 研究包络，不是无干涉装配 |
| R1 紧凑探索 | 更小挂坠 | 54×72×22 mm，R10 | 45–70 g | 条件化目标，需更小主板/电芯 |
| R2 | 6061 铝前壳 + 非金属天线帽 + 可拆后盖 | 76×104×34 mm，含挂点总高约 108 mm | 155–190 g | 单件金属结构研究样机，偏重 |
| R3 Lite | 亚克力平板盒 | 90×70×30 mm | — | 低成本自装实验机，不继承佩戴指标 |

R2 的结论很直接：**用现成计算/相机模组 + 单件金属结构，做不出轻巧挂坠**。它揭示的是代价，不是终点。下一轮轻量化需要缩计算平台、优化天线、改薄金属结构，而不是把当前模型整体缩小。

## 6. 功能范围

**首版做**

- 按键触发的短语音记录与拍照提问
- 会议模式 2 h 连续录音（先确认知情同意）
- 本地加密分片、断网续传、断电恢复
- 屏幕 + 振动 + 指示灯的明确状态反馈
- 实体双路采集许可开关（麦克风 / 相机）
- 服务器 ASR / OCR / 摘要 / 检索，结果带证据与待确认标识
- BLE 配网与状态；Wi-Fi 上传

**首版不做**（理由：授权边界、功耗、体积或可验证性）

- 全天自动拍摄、默认常开唤醒词
- 持续上传视频
- 本地通用大模型
- 光学变焦
- 独立蜂窝
- 未经确认的对外发信、日历变更或任务分派

## 7. 交互与状态

实体件：独立双路采集许可开关、有触感的助理键、相机/确认键、导航 ±、录制指示灯与摄像指示灯。上电默认不采集，状态灯由**实际已使能的采集轨**驱动，屏幕只是补充。

| 状态 | 用户看到/感到 | 失败或打断行为 |
|---|---|---|
| 锁定待机 | 锁图标；采集灯灭 | 硬件许可关闭，按键只提示解锁 |
| 就绪 | 电量、连接；屏幕短时唤醒 | 待机时长独立测量，不用录制续航代替 |
| 正在聆听 | 录音灯亮、计时、音量反馈 | 松键结束；越过最长指令时长提示并封存 |
| 已本地保存 | 勾选图标 + 明确文字 | 这一步成功才给保存振动；磁盘满/密钥不可用显示失败 |
| 等待联网 | 「已保存，联网后处理」 | 用户可取消队列；不伪装回答 |
| 正在理解 | 可取消进度；提示照片上传 | 超过 15 s 显示稍后查看 |
| 回答/候选事项 | 短回答、来源入口、待确认标识 | 助理键打断；确认键只确认屏幕当前对象 |
| 会议录制 | 录制时间、电量、存储、物理录音灯 | 停止后后台整理；网络变化不结束采集 |
| 低电/过温 | 原因、被暂停功能、剩余录制提示 | 先停预览/播报/批量上传，再封存关机 |

响应目标（需记录 P50/P95，冷启动单独统计）：按键反馈 ≤150 ms；断网保存结果 ≤1 s；拍照后「已保存」≤2 s；网络良好时云端首个有效回答 ≤5 s。

## 8. 系统方案与关键取舍

**主方案（R0 台架 / R1 功能台架）**：Linux SoC + 小 FPGA。

```text
4×PDM MIC ──► iCE40UP5K（同步采样 / 抽取 / 32-bit 采样计数 / 128 KiB 环形缓冲）
                    │ SPI + IRQ
                    ▼
              Zero 2 W (512 MB) ──► 加密分片 ──► Wi-Fi/TLS ──► 服务器
                    ▲
Camera Module 3 ────┘（CSI 直连，不经过 FPGA）
```

关键取舍：

| 决策 | 选择 | 代价 / 判定 |
|---|---|---|
| 计算平台 | 现成 Zero 2 W，不自研 DDR/RF | 尺寸与功耗受限；但把风险集中在可替换模组上 |
| 音频同步 | 独立 FPGA 做同相时钟采样与确定性缓冲 | 增加 0.08–0.20 W、1.2 V 电源与固件维护；**必须用实测证明收益**，否则下一版删除 |
| 相机 | Camera Module 3 AF + 数字裁切 | 无 OIS；2× 裁切只剩约 3 MP；不承诺 3 m 外小字可读 |
| 显示 | 1.69 英寸 ST7789V2，独立 SPI | 10 fps RGB565 约 10.75 Mbit/s；15 fps 超出 24 MHz SPI 预算 |
| 联网 | Wi-Fi 上传 + BLE 配网 | 2.4 GHz 共存；有效上传目标 ≥5 Mbit/s（非 PHY 速率） |
| 重 AI | 全部放服务器，设备只做采集/缓存/加密 | 依赖网络；不能解释为离线大模型设备 |

FPGA 保留门槛写得非常具体：**在服务器上传、拍照、SD 同步写入同时发生时，连续 2 h 四路采样无无法解释的缺口；故意暂停主机服务 200 ms 仍保持无损。** 如果普通音频 ADC + DMA 同样满足且功耗更低，FPGA 不进入量产版本。

## 9. 设计原则

1. **同意先于采集**：每次录制前确认参会者知情同意；冷启动、崩溃重启都不自动恢复采集。
2. **物理开关是硬保证**：开关切断 MIC/相机许可与电源/时钟，应用卡死也要停；但已上传的数据不能靠开关撤回，需要单独的取消/删除请求。
3. **本地成功才算成功**：UI 的「已保存」只对应本地原子落盘，不对应云端已理解。
4. **候选不等于决定**：模型输出必须能跳到原始音频区间/照片；负责人、期限、决定在用户确认前不产生任何副作用。
5. **不隐藏失败**：丢样、溢出、空间不足、密钥不可用、超时都要明确显示，不能用「大概齐」的状态糊过去。
6. **先证明再承诺**：每个高风险指标都绑定实测方法和通过条件；未通过就保持 `BLOCKED`。

## 11. 成本与产品路线

三条路线并存，不是三个互相替代的 SKU，而是三种研究假设：

| 路线 | 单台成本口径 | 定位 | 结论 |
|---|---|---|---|
| R1 量产目标 | 500 元/台（100 台分配） | 可挂佩 AI 助手 | 分配上限，不是可达证据 |
| R2 单台样机 | 1985–4530 元，留 25% 返工后约 2480–5660 元 | 金属壳功能/结构研究样机 | 单件 CNC 铝中框 450–1200 元是最大单项之一 |
| R3 Lite | 目标 296 元，区间 245–403 元 | 200–300 元自装实验机 | 近 300 元有条件；200 元无采购闭环 |

R3 的取舍很典型：借现成主控板、FPGA 板、相机板、麦克风板自行接线，不重设计 BGA/DDR 主板，不计外包焊接与开发人工；基础版不含电池、屏幕、GNSS、IMU、蓝牙。

## 13. 下一轮先做什么

按依赖顺序，而不是按「看起来最酷」：

1. **供电 / 热 / 佩戴台架**：真实电芯在低电量、拍照+上传峰值、35 °C 环境连续 2 h，记录各轨电压/峰值电流/效率、壳体热点与电池温度。
2. **音频连续性与物理停止**：4–8 人真实会议，上传/拍照/SD 写入并行，注入 200 ms 主机停顿；冻结软件时拨实体开关，确认硬件采集停止。据结果决定 FPGA 去留。
3. **带壳图像与无线**：装真实 FPC、金属散热件和电池，对比裸板/带壳 Wi-Fi 吞吐、BLE 共存、断网续传；0.5–3 m 拍白板/投影核查文字可读性。
4. 以上通过后，才冻结屏幕/电池/计算/音频/相机与接口矩阵，重建 KiCad 与 FreeCAD 真实装配。
