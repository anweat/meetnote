# 需求与交互基线

> 来源：[R0 产品基线与可行性](../iterations/MeetNote-R0/docs/01_产品基线与可行性.md)、[R1 产品与工程基线](../iterations/MeetNote-R1-design/产品与工程基线.md)｜2026-09-29

本文把 R0 的 11 条产品需求与 R1 的交互定义合并成一份可验收的基线。每条需求都写「验收办法」，因为本项目的基本原则是：**没有验收方法的指标不进入基线**。

---

## 1. 产品需求基线（R01–R11）

| ID | 基线 | 验收办法（待实测） |
|---|---|---|
| R01 | 桌面 4–8 人、距离 0.5–3 m、普通会议室；语音优先，2 小时连续记录 | 8 人真实会议，混响和空调噪声下人工标注对照 |
| R02 | 每次录制前由操作者确认所有参会者知情同意；默认上电不录制，断电重启不自动恢复采集 | 冷启动、崩溃重启、撤回同意演练 |
| R03 | 实体双极开关切断 MIC_CAPTURE 许可和 CAMERA_CAPTURE 许可；分别有硬件状态灯，软件显示补充 | 卡死应用/内核，切断许可后示波器确认采集停止；验证旁路/反向供电 |
| R04 | 摄像头仅按键拍摄白板、投影和材料；预览最多 30 s，默认不上传视频 | 审查上传 manifest 中只有音频与手动静态图 |
| R05 | 1×/1.5×/2× 数字裁切，自动对焦，保留原图；2× 只剩约 3 MP，不承诺远处小字可读 | 3 m 白板/投影文字清晰度和闪烁测试 |
| R06 | 断网加密暂存、重连续传，不覆盖未确认上传的数据 | 断网 2 h，50 次随机中断重启，文件哈希和连续时间轴对照 |
| R07 | 断网不会阻止开始录制；存储不足、密钥不可用、硬件许可未开启会阻止录制 | 逐个故障注入 |
| R08 | 自动摘要、负责人、期限和决定只标为候选；用户确认前不分派、不推送给他人 | 每条结果可跳转原始音频时间范围及照片 |
| R09 | 操作：实体许可开关、录制/停止键、拍照键、裁切 ±；录制红灯、摄像黄灯、上传蓝灯、错误闪烁 | 无需手机也能开始/停止并辨认错误；BLE 仅配网/状态 |
| R10 | 目标环境 10–35 °C、室内无防水要求；外壳触及面目标 ≤43 °C，电池充电温度遵从电芯规格 | 35 °C 恒温、满负荷和充电测试；不是安全认证结论 |
| R11 | 保留期默认 30 天、可导出/删除；权限按会议隔离；首次使用设置设备所有者 | 越权和删除审计，失窃威胁模型检查 |

> 这 11 条是产品级承诺的候选基线，不是已实现功能。R0 的验收记录显示：R03 的硬件门控只有接口占位，R06/R07 只有磁盘模拟测试，R11 只有设计草案。

## 2. R1 增补：定位与 MVP

R1 将定位调整为「可挂佩 AI 助手」，会议记录降为**核心模式之一**。新增三条 MVP 需求：

| 动作 | 用户路径 | 输出与成功条件（目标，未实测） |
|---|---|---|
| **记住这件事** | 按住助理键说话，松开发送；断网时先存本地 | 屏幕和短振动明确「已保存」或「保存失败」；不能把已保存显示成云端已理解 |
| **看一下这个** | 相机键唤醒后屏取景，再按拍照；长按助理键补充问题 | 照片与问题绑定到同一请求；识别不清时要求重拍，保留原图 |
| **帮我回顾** | 询问自己已授权的记录；在后屏或手机看摘要/待办 | 每条结论能追到记录时间与证据；没有找到就明确说未找到 |

会议模式是独立长录制模式：启动前确认参会者知情同意，连续记录目标 2 h。胸前位置优先收佩戴者语音，**不能承诺等效桌面全向阵列**；多人会议建议桌面摆放。

## 3. 交互映射

### 3.1 实体控制

| 控件 | 行为 |
|---|---|
| 助理键 | 按住说话、松开提交；播报中按下立即取消播报并进入新一轮聆听 |
| 相机/确认键 | 单击唤醒取景；取景中单击拍照；确认键只确认屏幕当前对象；长按返回/取消 |
| 导航 ± | 调数字裁切（1× / 1.5× / 2×） |
| 双路采集许可开关 | 分别切断麦克风、相机；关闭时新采集必须停止，挂起请求取消上传 |
| 指示灯 | 录制红灯、摄像黄灯、上传蓝灯、错误闪烁；由实际采集轨/门控输出驱动 |

会议开始必须从模式页**显式确认**，不能因长按误触直接启动。

### 3.2 屏幕与反馈

- 外侧（镜头面）：摄像/录音灯、镜头保护圈、品牌小标。
- 靠身体一面：1.69 英寸彩屏候选（ST7789V2，240×280）。
- 默认反馈：屏幕文字 + 短振动；语音播报由用户开启；会议模式默认静音。
- 首版助理对话采用**半双工**，避免把自己的播报当成用户说话；会议录制时禁止外放回答，但继续采集会议音频。

### 3.3 状态机

| 状态 | 用户感知 | 失败/打断 |
|---|---|---|
| 锁定待机 | 锁图标、采集灯灭 | 硬件许可关闭，按键只提示解锁 |
| 就绪 | 电量、连接；屏幕短时唤醒 | 待机时长独立测量 |
| 正在聆听 | 录音灯亮、计时、音量反馈 | 松键结束；超长提示并封存 |
| 已本地保存 | 勾选 + 明确文字 | 磁盘满/密钥不可用显示失败 |
| 等待联网 | 「已保存，联网后处理」 | 用户可取消队列，不伪装回答 |
| 正在理解 | 可取消进度 | 超过 15 s 显示稍后查看 |
| 回答/候选 | 短回答、来源入口、待确认标识 | 助理键打断；确认键只确认当前对象 |
| 会议录制 | 时间、电量、存储、物理录音灯 | 网络变化不结束采集 |
| 低电/过温 | 原因、被暂停功能、剩余时间 | 依次停预览/播报/批量上传，再封存关机 |

### 3.4 响应目标

记录 P50/P95，冷启动单独统计：

| 指标 | 目标 |
|---|---|
| 就绪状态按键反馈 | ≤150 ms |
| 断网保存结果（短指令结束后） | ≤1 s |
| 拍照后展示「已保存」 | ≤2 s |
| 网络良好时云端首个有效回答 | ≤5 s |

## 4. 隐私与同意

- 首次使用设置设备所有者；权限按会议隔离。
- 上电默认不采集；采集许可由实体开关与硬件逻辑共同决定。
- 开关关闭只停止**新采集**并取消挂起上传；已在服务器处理的内容需另发取消/删除请求——**不能声称物理开关会撤回已上传数据**。
- 保留期默认 30 天、可导出/删除；删除审计、密钥销毁与备份过期联动仍需生产实现。
- 唤醒词未来如加入，必须显式开启，并承认麦克风处于采样状态，不能声称「完全未监听」。

## 5. 非目标（首版明确不做）

| 不做 | 原因 |
|---|---|
| 全天自动拍摄、全天候生活记录 | 授权边界、功耗、存储与伦理 |
| 默认常开唤醒词 | 同上；且待机功耗未解决 |
| 持续上传视频 | 带宽、隐私与成本 |
| 本地通用大模型 | 512 MB / 64 MB 平台均不成立 |
| 光学变焦 | 体积与供应链 |
| 独立蜂窝 | 功耗、认证与成本 |
| 未经确认的对外发信、任务分派、日历变更 | 副作用必须人工确认 |
| 防水/IP 等级承诺 | 密封路径未完成 |

## 6. 待验证的产品假设

1. 高频用户真的愿意佩戴——等重模型 ≥30 min 日常动作测试。
2. 按键说话比手机开应用更方便——10 个相同任务的对比实验。
3. 联网路径可接受——家庭/办公室 Wi-Fi 与手机热点切换各 20 次。
4. 简短回答有用——若用户更需要长文本，应优先手机显示，避免屏幕不断加大。
5. 胸前麦克风在会议场景可用——胸前 / 手持 / 桌面三姿态对比，含衣物摩擦与扬声器回采。
